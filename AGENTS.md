# EU5 mod workspace

**Europa Universalis V** (Paradox, Clausewitz/Jomini engine) modding environment. Mods are pure
PDXScript text files — no compilation, no runtime SDK. The game is **Windows-only**.

## Directory map

- `docs/` — knowledge layer. Start at [`docs/INDEX.md`](docs/INDEX.md) for the map; the authoring
  rules (override/load-order/localization/metadata) live **only** in
  [`docs/eu5-modding-conventions.md`](docs/eu5-modding-conventions.md).
- `game-scripts/` — vanilla script mirror (generated by `sync_game_scripts`, git-ignored): the
  **context you must load before writing mods** (PDXScript has no self-describing API — without it
  you cannot write correct overrides/INJECT; mirror it with `sync_game_scripts` before authoring).
- `.pi/skills/` — three role-split skills (**what each covers / when to use it is in its own description**; Pi keeps them in context, so read the matching one). This repo's step guidance lives there, not in the product prompt.
- `.pi/extensions/` — tools: paths (`try_set_game_dir` ensure / `set_game_dir` record / `check_game_paths` verify), runtime (`check_runtime` / `install_runtime` — EU5 has none), `validate_mod`, `install_mod`, `sync_game_scripts` (mirror vanilla context); trust the capabilities/side-effects each tool declares.
- `reference/example_mod/` — a runnable sample that passes `validate_mod`.
- `mod-repo.json` — machine-readable game and environment declaration. 其中 `workshop.supported` 声明本游戏**有没有创意工坊**；`workshopDir` 只是只读参考（不参与安装），判定规则见 SKILL 的「路径工具」段。

## Runtime state file

`.gamer-agent.local.json` (**under this workspace directory**) is the single source of truth for path
state, read/written by the tools in `.pi/extensions/`. **Only trust the copy in this workspace** — the
machine may have same-named files elsewhere (other clones, leftover state); using those leads to wrong
conclusions. **"Ready" means the recorded values + the tool's result** — seeing a directory with `ls`
does not mean it is recorded (the workspace panel, `validate_mod`, `install_mod`, and `sync_game_scripts`
all read the recorded state). Field meanings are in `.pi/skills/setup-workspace/SKILL.md`.

## Session roles and write boundary

The workspace supports two roles, set by the session, not chosen by the agent:

- **Q&A (Game Helper):** read-only. Answer game-mechanics / mod-API questions from `docs/`; may run
  the read-only tools `check_game_paths` (verify paths), `check_runtime`/`install_runtime` (both
  report "no dependencies"), and `validate_mod` (lint); must **not** write or edit any mod file,
  locate/record paths, or sync vanilla scripts.
- **Authoring:** write only under `your_mods/<ModName>/`. Whether writing is allowed, and to which
  mod directory, is set by the session role and binding — not by reading this file.

Everything else (`docs/`, `.pi/`, `reference/`, `mod-repo.json`) is maintained by the repo owner and
is read-only.

## Author-time checklist (before writing)

Keep these in mind while authoring, so most `validate_mod` failures never happen:

- Keep `{`/`}` and `"` balanced; `#` is a line comment (literal inside strings).
- When overriding a vanilla-defined object in a keyword folder, prefix it with
  `REPLACE:`/`INJECT:` (top-level block only).
- Use load-order prefixes (`zz_` late, `00_` early, `98_`/`99_`) so overrides load after their
  targets.
- Localization YAML: UTF-8 **with BOM**, filename ends `_l_<language>`, first line `l_<lang>:`,
  entries `key: "value"`.
- Do not leave `temp_*` / `_tmp_*` scratch files or editor backups in the mod directory.

## Validation

After finishing (or changing) a mod, run `validate_mod` on `your_mods/<ModName>/` and clear every
ERROR before ending the turn. The linter checks syntax/conventions only; it is not a semantic
validator.
