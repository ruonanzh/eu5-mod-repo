# EU5 modding docs index

A curated map of the knowledge layer under `docs/`.
**Load selectively.** Read this index first. Then open only the one or two pages that the current
task needs, instead of pulling the whole `docs/` directory into context.

## Lookup hierarchy (which source is authoritative for what)

| You need | Source |
|---|---|
| Exact effect, trigger, and modifier names, and their scopes | [`script_docs/`](script_docs/) and [`data_types/`](data_types/) — game-generated dumps, authoritative |
| Exact vanilla object definitions, field values, INJECT targets, and loc keys | `game-scripts/` (the vanilla script mirror, generated by `sync_game_scripts`), or the local game directory recorded by `try_set_game_dir` |
| Mechanics concepts and how-to method (mod API) | [`mod-wiki/`](mod-wiki/) (a curated wiki snapshot) |
| Authoring rules and the reason behind them | [`eu5-modding-conventions.md`](eu5-modding-conventions.md) |

> **Dumps compared with `game-scripts/`.** The dumps list what exists: effect, trigger, and
> modifier names with their scopes. `game-scripts/` holds the vanilla script source: object
> definitions and field values. Grep `game-scripts/` for exact values, INJECT targets, and loc
> keys. Use the dumps to check that a name exists and to read its scope. Both are text-only, and
> both come from the local game directory. Prefer `game-scripts/` after you run
> `sync_game_scripts`.

- **Start here:** [`eu5-modding-conventions.md`](eu5-modding-conventions.md). This cheat-sheet
  covers override and `INJECT` semantics, ASCII load order, localization, and metadata. It answers
  most authoring questions on its own. Read the pages below only when you need more depth.
- **Exact names, scopes, and signatures: use the game dumps.** To find whether an effect, trigger,
  or modifier exists, and in which scope, use the
  [game-generated reference dumps](#game-generated-reference-dumps-authoritative). The running
  game exports them, so they match the installed version. Prefer them over the wiki, which is a
  periodic copy and can lag.
- **Concepts and how-to method: use [`mod-wiki/`](mod-wiki/), a curated wiki snapshot.** It
  explains how the systems work and the mod API concepts, in 118 pages under 9 topic directories.
  See [`mod-wiki/INDEX.md`](mod-wiki/INDEX.md). The live wiki (eu5.paradoxwikis.com) is newer.
  Re-sync with `scripts/crawl_eu5_wiki.py` when it drifts.

> `validate_mod` checks syntax and conventions only. These docs are the reference for semantics:
> which scopes, effects, triggers, and types exist. Always prefer them over a guess.

## Game-generated reference dumps (authoritative)

The running game exports these dumps through the `script_docs` and `dump_data_types` console
commands. They are plain text, one entry per record, and easy to grep. They match the installed
game version, so they are the source of truth for exact keywords.

| Dump | Entries | Load it when you need to |
|------|--------:|------------------------|
| [`script_docs/effects.log`](script_docs/effects.log) | ~1490 | Check an **effect** name and its supported scopes and targets. |
| [`script_docs/triggers.log`](script_docs/triggers.log) | ~1725 | Check a **trigger** name and its supported scopes and targets. |
| [`script_docs/modifiers.log`](script_docs/modifiers.log) | ~2333 | Check a **modifier** tag and its category. |
| [`script_docs/event_targets.log`](script_docs/event_targets.log) | ~326 | Check a **scope link** or event target and its input and output scopes. |
| [`script_docs/on_actions.log`](script_docs/on_actions.log) | ~244 | Check an **on_action** hook name and its expected scope. |
| [`script_docs/custom_localization.log`](script_docs/custom_localization.log) | ~927 | Check a **custom localization** promote and its entries. |
| [`data_types/data_types_*.txt`](data_types/) | ~27000 | Check a **GUI or script data-type promote or function** (name and return type) for `.gui` datamodel bindings, scripted GUI, and script values. The dumps are the only source, because the wiki has no equivalent. |

> `data_types/` has no wiki counterpart, so it is the only reference for GUI and script promotes
> and functions. The files are split by area: `_gui`, `_script`, `_common`,
> `_internalclausewitzgui`, and a large `_uncategorized`.
